## Висновок
У ході роботи створено Postman Collection `Lab 4 - API Testing` зі змінною `baseUrl` та трьома запитами: GET із Query Parameters, POST із JSON Body і негативний тест `/status/404`. Для кожного запиту написано автоматизовані перевірки в After response за допомогою `pm.test()`, `pm.response` та `pm.expect()`. Усі 11 перевірок мають результат PASSED; у негативному тесті відповідь HTTP 404 є очікуваною за Test Basis, тому тест пройдено. Також з'ясовано, що Postman Echo повертає Query Parameters у полі `args`, а JSON-тіло — у полі `data`.

## Відповіді на контрольні питання
1. Expected Result визначається за Test Basis (вимогами), а не за фактичною відповіддю. Інакше тест підлаштовується під поведінку системи, включно з її помилками, і ніколи не виявить дефект.
2. Collection — контейнер для впорядкованого зберігання Requests, їхніх тестів і змінних; її можна запускати цілком, експортувати та передавати іншим.
3. `{{baseUrl}}` — змінна колекції з базовою адресою. Вона підставляється в URL, тож адресу достатньо змінити в одному місці.
4. Postman Sandbox — ізольоване середовище виконання JavaScript-скриптів (Pre-request та After response) усередині Postman.
5. `pm` — глобальний об'єкт Postman Sandbox, через який скрипт отримує доступ до request, response, змінних, `pm.test()` і `pm.expect()`.
6. `pm.response` — об'єкт відповіді сервера: status, headers, body, час відповіді.
7. Розпарсене тіло відповіді як JavaScript-об'єкт (з JSON).
8. Створює іменований автоматизований тест; результат відображається у Test Results як PASSED або FAILED.
9. Назва тесту (рядок), яка показується в результатах.
10. Callback містить код перевірок (assertions): якщо хоч одна перевірка кидає помилку, тест FAILED.
11. Створює assertion у стилі Chai: порівнює фактичне значення з очікуваним за допомогою ланцюжка `.to...`.
12. Actual Value — значення `actual` у дужках `pm.expect()`, тобто фактичне значення з відповіді API (наприклад, `json.args.name`); `expected` — очікуване за Test Basis.
13. `.to.eql()` — глибоке порівняння фактичного значення з очікуваним (для примітивів, об'єктів і масивів).
14. `.to.have.property()` — перевіряє, що об'єкт має вказану властивість (за потреби й її значення).
15. `.to.be.a()` — перевіряє тип значення (наприклад, `"number"`, `"string"`, `"object"`).
16. Один Request має кілька незалежних очікувань (статус, заголовок, значення полів). Окремі тести дають точніший результат: видно, яка саме перевірка не пройшла.
